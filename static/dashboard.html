Every purchase walks the same path.

Segments are sized by where the 67 eval purchases were actually decided.

Catalog & allowlist

First, unknown vendors, unsafe URLs, empty purposes and injected instructions stop here.

Caps & budgets

Then per-purchase, daily and 30-day vendor limits, in whole cents.

AI guard

Then the AI judges what rules can't express. If it's unavailable, a human decides.

Human approval

Then anything over $60 waits for the owner.

PayPal payment

Finally the tab pays, through PayPal sandbox.

A prepaid tab, funded by PayPal

Orders v2 create → approve → capture. Integer micro-dollar ledger; parallel buys can't overspend.

Vendor budgets

Each approved vendor gets its own rolling 30-day budget. Others are blocked before any AI runs.

Human approval over $60

Big buys return 202 with a PayPal link. The owner pays that one purchase, or rejects it.

Refund windows on a live timeline

Budgets, approvals, refund deadlines and renewals on a Bryntum Scheduler, moved by PayPal webhooks. The scheduler proposes refunds; you confirm.

Verified webhooks, SSRF-safe fetching

Every PayPal event is checked with verify-webhook-signature and applied exactly once. Every redirect hop must resolve to a public IP.

An MCP server for any agent

The same guarded tab as MCP tools (buy, get_tab, request_topup…) over Streamable HTTP. No owner tools are exposed.
