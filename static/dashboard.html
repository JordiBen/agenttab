Bar widths show where our 67 test purchases were actually decided.

  1. Your rules.

    You pick the vendors, a budget for each, a daily cap and an approval limit.

  2. Hard checks.

    Unknown vendors, unsafe links and over-budget buys stop here, before any AI runs.

  3. Claude checks the rest.

    Is the purpose really business? Is someone trying to trick the agent? If Claude is unavailable, you decide, never the agent.

  4. You approve big buys.

    Anything over $60 becomes a PayPal hold. Money is taken only after delivery; if delivery fails, the hold is released.

For developers

  
    
   
  • PayPal: Orders v2 checkout funding, AUTHORIZE → capture after delivery, void on failure, Vault saved card, refunds per capture, signature-verified webhooks applied once, PayPal-Request-Id per operation.
    • 
   
  • Claude guard: Claude with JSON-schema verdicts; errors, refusals and timeouts go to a human, never to auto-approve.
    • 
   
  • MCP: six guarded tools over Streamable HTTP; agent key only; no owner tools. Connect a client →
    • 
   
  • Safety: integer-cent ledger, per-agent locks, parallel buys can't overspend, SSRF-safe fetching, automated tests.
    •

Connect an MCP client MCP 2026-07-28

    
The same agent, as guarded tools for Claude, Cursor or any MCP client: get_catalog, get_tab, buy, request_topup, list_purchases, mark_used. Every call goes through the same guard and tab. No owner tools are exposed. buy answers with an outcome: bought, approval_required, payment_required, blocked or frozen; agents that pay vendors from a saved card can also get card_required, payment_failed, payment_unknown or payment_flagged.
